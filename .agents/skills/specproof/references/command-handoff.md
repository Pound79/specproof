# 人にコマンドを渡して再開する

エージェントが検証ゲートのコマンドを流せないときに、人に 1 行のコマンドを渡し、貼られた結果を受けて
続けるための様式。流せないことを理由に検証ゲートを省略しない。

## 使う場面

- 実際に流して、書き込み・ネットワーク・資格情報などの環境の制限で失敗したとき（sandbox で作業ツリーや
  `.git` に書けない、など）。流す前に推測で使わず、失敗した出力を 1〜2 行添える
- 人が「コマンドは自分で流す」と伝えたとき

「設定のコマンドを実行する前の確認」（各 SKILL.md）は、人に渡す場合も先に済ませる。渡すのは確認を通った
展開後のコマンドだけ。人の手元では、エージェントの sandbox の制限が無く、人の資格情報で動く。様式にそのことと
確認の結果（比較先・差分のあったファイル・承認の有無）を書く。

## 渡す様式（ゲートごとに 1 つ）

```
ゲート: <名前>（例: 生成と型検査）
注意: sandbox の外で、あなたの権限と資格情報で動きます。設定の確認: <比較先> と比べて <差分のあったファイル / 差分なし>（<承認済み / 承認待ち>）
流すコマンド（設定ファイルのあるディレクトリで 1 行）:
  <コマンド 1> && <コマンド 2> && <コマンド 3>; echo "exit=$?"
期待する結果:
  - <コマンド 1>: 終了コード 0。<件数など>
  - <コマンド 3>: passed N / failed M。落ちるのは @red-contract の <シナリオ名> だけ
貼ってほしいもの: 出力の最後の 30 行ほどと exit= の行
```

- コマンドは `&&` でつなぎ、途中で落ちたら後ろを流さない。末尾の `; echo "exit=$?"` で終了コードを残す。
  ディレクトリを移るなら `( cd <リポジトリ相対のパス> && ... )` のように括弧の中で移る
- リポジトリから取った値（パス・link id など）は単一引用符で囲む。`'` や改行などシェルが解釈する文字を含む値は
  コマンドに入れず、値とともに人に示して扱いを聞く
- 期待する結果は、照合できる形で書く: 件数（生成数・`passed` / `failed` の数）、`clean`、想定どおりの RED に
  なるシナリオの名前と件数。「通ること」だけにしない
- 状態を変えるコマンド（`{{config:commands.traceabilityUpdate}}`、コミット、ブランチの作成）は、検証のコマンドと
  同じ行に入れない。検証の結果を確かめた後に、別のゲートとして渡す
- 1 回に渡すのは、次の判断に要るゲートだけ。後のゲートは結果を見てから渡す

## 結果を受けて続ける

1. 貼られた出力を期待する結果と照合し、ゲートごとに PASS / FAIL / SKIPPED(理由) を決める。出力が無く
   「通った」とだけ言われたら、PASS ではなく「人の申告（出力未確認）」と書く
2. 期待と違えば、自分で流した場合と同じく診断して直し、直したことと次に流すコマンドを同じ様式で渡す。
   自己修正の回数の上限（各 skill の「2 回まで」）に数える
3. 出力が切れていて判定できなければ、足りない部分だけを求める
4. レポートの検証結果には、そのゲートを人が実行したことを添える（例: `smoke: FAIL（想定どおりの RED: @red-contract 3 件）・人が実行`）
